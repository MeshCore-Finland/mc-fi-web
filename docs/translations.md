# Finnish and English content

Finnish is the source of truth. Pair articles by their language-independent path under `src/content/docs/fi/` and `src/content/docs/en/`, regardless of `.md` or `.mdx` extension. Translate every published Finnish article; keep source drafts as drafts. Missing English articles use Starlight's Finnish fallback until a translation is published.

## Dates and the source fingerprint

Use quoted calendar dates (`YYYY-MM-DD`), with no time of day. Dates describe completed checks, never just saving, formatting, merging or publishing a file.

| Field                   | Location                  | Meaning                                                                                                                                                 |
| ----------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lastReviewed`          | Finnish article, optional | A reviewer checked that the technical information and instructions are still valid. Omit until that has happened.                                       |
| `translationChecked`    | English article           | Date of the last full comparison with Finnish, including an assisted or automated comparison. This does not claim human approval or technical validity. |
| `translationSourceHash` | English article           | Generated SHA-256 fingerprint of the Finnish article used for that comparison. Keep it together with `translationChecked`.                              |

```yaml
# Finnish: only after an actual technical validity review
lastReviewed: '2026-10-21'
```

```yaml
# English: generated by the recording command after a full comparison
translationChecked: '2026-10-21'
translationSourceHash: 'sha256:…' # The actual value has 64 hexadecimal digits.
```

One translation date covers updating and checking, including a comparison that required no edits. Do not maintain a separate sync date. Do not copy `lastReviewed` into English or advance it as part of translation. The footer displays available dates; the fingerprint is contributor metadata and is not displayed.

The fingerprint covers the full Finnish body (including MDX imports, image references, comments and commands) and all front matter except these three review fields. Parsed front matter is sorted recursively, so key ordering, comments and YAML quoting do not affect it. CRLF is normalized to LF; trailing whitespace at the end of the article is ignored. Other body formatting changes can trigger a comparison. A review-date change alone does not.

A matching fingerprint means **source unchanged since comparison**. It does not certify translation quality, subsequent English edits, technical accuracy or shared component text. It is not a fingerprint of English. Git records individual edits and PR review records approval.

## Find work and record a comparison

```sh
npm run check:translations
```

The read-only report lists article paths:

- `missing`: English is missing or remains a draft while Finnish is published.
- `unchecked`: English exists but has no complete date/fingerprint pair.
- `source-changed`: Finnish differs from the recorded fingerprint.
- `source-unchanged`: Finnish is unchanged since the recorded comparison.
- `orphan`: English has no corresponding Finnish article.
- `draft`: Finnish is a draft; translation is not required yet.
- `published-draft`: English is published although Finnish is a draft; reconcile publication status.

Freshness findings are advisory by default. `npm run check:translations -- --strict` fails when any path needs attention; ordinary Finnish drafts are excluded. Invalid front matter or arguments always fail. The report runs independently of the build and does not block publishing. There are no age-based warnings.

For each page needing comparison:

1. Read current Finnish and existing English. Use Git history to inspect source changes when helpful. An unchanged source may still benefit from translation improvements.
2. Edit the existing English, preserving contributors' wording and terminology improvements. Avoid replacing a whole translation just because the source changed.
3. Compare the entire page: title, description, body, links, tables, captions, alt text, tabs and interactive content. Keep source facts, qualifications and limitations intact.
4. After the full comparison, explicitly record it with the date on which it happened:

   ```sh
   npm run check:translations -- --stamp users/start --date 2026-10-21
   ```

   Substitute the page path and actual date. This updates only that English article's translation metadata, preserving the body and YAML comments. It does not translate, judge quality, update Finnish review dates or grant approval. It refuses missing articles and drafts. Never run it merely to silence the report.

5. Run `npm run build`, `npm run check:links` and `npm run check:translations -- --strict`. Inspect changed pages in both languages, including navigation, FAQ anchors, screenshots, tabs and narrow viewports.

The recording command can reformat English front matter and normalizes line endings. Builds and ordinary edits never refresh dates or hashes automatically.

## Contributor improvements and factual changes

Good translation PRs become the maintained English text. For wording, grammar or terminology improvements, keep the existing source hash and `translationChecked`: they still describe the last full comparison. Update both only when the contributor compares the whole page with current Finnish. A merge or English-only edit is not itself such a comparison.

If English needs a factual correction or new useful information, update Finnish too, ideally in the same PR, then reconcile English against it. Flag suspected source errors needing a separate validity review in the PR rather than silently correcting only English or stamping a technical review that did not happen.

When changing Finnish, update English in the same PR or state that translation work remains. The report detects the changed source automatically. If a change only affects formatting, a comparison may legitimately require no English edits.

## Translation conventions and glossary

Use natural, clear English while preserving meaning and the source's friendly tone. Keep product names, configuration keys, literal UI labels, commands, radio parameters, URLs, region identifiers and cryptographic values unchanged. Translate surrounding explanations. Preserve literal packet examples when byte sizes or timings are discussed. Keep CLI snippets executable and preserve source values, including example placeholders; explain placeholders in English outside snippets where needed.

Add agreed terminology decisions here so later passes preserve them. Descriptive workflow tab labels are `Web GUI`, `Mobile app` and `Command line`; preserve related `syncKey` values.

Use `DocLink` to retain the reader's language. Preserve explicit FAQ/question IDs, component props and code behavior. Update heading-derived anchor references when translating headings. Screenshots may be reused; translate alt text and captions while retaining literal UI labels.

## Shared UI and other pages

The homepages share `HomePage.astro` and use `src/content/i18n/fi.json` and `en.json`; the 404 page and other components can contain their own text. Compare these separately during full-site passes. The schema checks dictionary key coverage, but article fingerprints do not track dictionary values, component internals, image pixels, sidebar labels or external destinations. Neither unchanged keys nor a successful build proves those translations are current.
